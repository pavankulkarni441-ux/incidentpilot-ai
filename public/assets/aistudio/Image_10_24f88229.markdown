## Brand & Style
The design system establishes a high-stakes, operationally disciplined visual framework built for site reliability engineers, platform architects, and incident commanders. The visual tone balances technical authority, surgical precision, and calm clarity during high-severity system outages.

The visual style is **Technical Modernism**—a disciplined utility framework prioritizing rapid cognitive parsing, data density, and verifiable telemetry over decorative embellishment. By eliminating glassmorphism, aggressive glowing gradients, and skeuomorphic excess, the interface centers user attention on signal fidelity, AI audit trails, trace telemetry, and unambiguous human-in-the-loop decision checkpoints. Visual hierarchy relies strictly on calibrated structural borders, micro-status indicators, and precise spatial pacing.

## Colors
The color architecture relies on deep, non-fatiguing charcoal and slate baselines paired with deliberate, high-contrast semantic indicators.

### Canvas & Surface Hierarchy
- **Canvas Base (`#0B0F17`)**: The global application bedrock for telemetry viewports and incident war-rooms.
- **Surface Primary (`#111827`)**: Standard container level for toolbars, incident timelines, and analytical panels.
- **Surface Elevated / Hover (`#1F2937`)**: Interactive surfaces, expanded log rows, and flyout inspector drawers.
- **Surface Subdued / Inset (`#080C13`)**: Dedicated for code blocks, terminal output, and query terminals.

### Structural Dividers & Borders
- **Border Default (`#1F2937`)**: Low-contrast internal division between sibling components.
- **Border Crisp / Active (`#374151`)**: Card perimeters, input field boundaries, and docked panel borders.
- **Border Focus / Selected (`#3B82F6`)**: Applied to focused terminal inputs and selected incident streams.

### Semantic Triage Accents
- **Primary Electric Blue (`#3B82F6`) / Deep Blue (`#2563EB`)**: Human action confirmation, active filtering, and primary interactive affordances.
- **Critical Failure Red (`#EF4444`)**: Severe incident states (SEV-0/SEV-1), broken circuit breakers, and unmitigated downtime alerts.
- **Warning Amber (`#F59E0B`)**: Latency spikes, anomalous automated hypothesis confidence drops, and pending manual interventions.
- **Operational Green (`#10B981`)**: Resolved states, health checks, continuous delivery passing, and autonomous verified rollbacks.
- **Neutral Muted Slate (`#6B7280`)**: Supplemental timestamps, inactive trace spans, and secondary metadata.

## Typography
Typography is paired to separate narrative and contextual analysis from raw telemetry data:

1. **Inter** serves all global layout labels, analytical explanations, system summaries, and incident retrospectives. It provides neutral, fatigue-resistant reading under stress.
2. **JetBrains Mono** governs all system identifiers, traces, error codes, payload snippets, status tags, and metric quantifiers. It features explicit distinction between ambiguous characters (`0` vs `O`, `l` vs `1`) and tabular figures (`tnum`) enabled globally to keep dynamic operational values vertically aligned across real-time feeds.

## Layout & Spacing
The layout model employs a responsive, fluid grid designed for extreme data efficiency and dense multi-window diagnostic monitoring.

### Responsive Structure & Breakpoints
- **Desktop (1280px and above)**: 12-column variable grid, `gutter: 1rem`, `margin: 1.5rem`. Enables persistent dual-pane workflows (e.g., active telemetry graph pane alongside an AI incident reasoning stream).
- **Tablet / Small Display (768px - 1279px)**: 8-column layout, `gutter: 1rem`, `margin: 1.25rem`. Right-side inspection panels collapse into docked overlay drawers.
- **Mobile (Below 768px)**: 4-column layout, `gutter-mobile: 0.75rem`, `margin-mobile: 1rem`. Focus shifts strictly to incident escalation, timeline reading, and one-tap approval actions.

### Spacing Rhythm
Spacing is calculated on a 4px/8px modular scale. Tight padding (`space-xs` to `space-md`) preserves screen real estate for logs and metric graphs, while container gaps (`space-lg` to `space-2xl`) cleanly segregate independent system subsystems without heavy structural elements.

## Elevation & Depth
Depth is constructed through **tonal surface stacking** and **crisp 1px borders** rather than diffuse drop shadows.

- **Level 0 (Base Canvas)**: `#0B0F17`. Deepest coordinate space, housing graph grids and workspace canvasing.
- **Level 1 (Card & Module Layer)**: `#111827` enclosed by a crisp `#374151` or `#1F2937` border. Used for metric cards, diagnostic logs, and evidence sidecars.
- **Level 2 (Popovers, Flyouts, & Menus)**: `#1F2937` with a 1px border of `#374151`. Supported by a minimal directional shadow: `0 4px 12px rgba(0, 0, 0, 0.4)`. No color-tinted glows or frosted blurs are permitted.
- **Level 3 (Modal / Interruption Dialogs)**: `#111827` framed by `#374151`, anchored over an opaque modal veil (`rgba(11, 15, 23, 0.8)`). Reserved for destructive rollbacks, cluster teardowns, and high-privilege remediation triggers.

## Shapes
The design system adopts a **Soft / Compact geometry** (`roundedness: 1`). Radii are strictly bounded:
- Base inputs, buttons, status chips, and table selections utilize `0.25rem` (4px).
- Enclosing diagnostic cards and flyout panes utilize `0.5rem` (8px).
- Modal shells utilize `0.75rem` (12px).

Pill shapes and circular controls are disallowed except for standard avatar indicators and pulsing live-connection status dots. This compact geometry reinforces the technical, tool-first aesthetic common to performance-critical systems.

## Components

### Buttons
- **Primary**: Background `#3B82F6`, label `#FFFFFF` in `label-md` JetBrains Mono, border radius `0.25rem`. Hover state transitions to `#2563EB`. Used exclusively for principal system actions (e.g., "Deploy Fix", "Acknowledge Incident").
- **Destructive**: Background `#EF4444`, label `#FFFFFF`. Hover transitions to `#DC2626`. Used for system aborts, traffic drops, and rolling restarts.
- **Secondary / Outline**: Background transparent, border 1px solid `#374151`, label `#D1D5DB`. Hover applies background `#1F2937` and border `#4B5563`.
- **Ghost**: Background transparent, border transparent, label `#9CA3AF`. Hover applies background `#1F2937` with label `#FFFFFF`.

### Chips & Status Badges
Badges are non-pill shapes (`0.25rem` radius) rendered in `label-sm` with tabular numerals.
- **Critical (SEV-0/SEV-1)**: Background `rgba(239, 68, 68, 0.12)`, border 1px solid `rgba(239, 68, 68, 0.4)`, text `#F87171`. Includes a persistent 6px solid square indicator.
- **Warning**: Background `rgba(245, 158, 11, 0.12)`, border 1px solid `rgba(245, 158, 11, 0.4)`, text `#FBBF24`.
- **Healthy / Resolved**: Background `rgba(16, 185, 129, 0.12)`, border 1px solid `rgba(16, 185, 129, 0.4)`, text `#34D399`.
- **AI Hypothesis Badge**: Background `rgba(59, 130, 246, 0.12)`, border 1px solid `rgba(59, 130, 246, 0.4)`, text `#60A5FA` with confidence score percentage (e.g., `CONF: 94.2%`).

### Cards & Metric Panels
Constructed with background `#111827`, border 1px solid `#374151`, and internal padding of `space-lg`. Metric cards display the label in `body-sm` (`#9CA3AF`), the primary metric in `headline-lg` (`#F9FAFB`), and real-time sparkline telemetry at the baseline. Hovering over a card brightens the border to `#4B5563`.

### Input Fields & Search Bars
- Background `#080C13`, border 1px solid `#374151`, text `#F9FAFB` in `label-md`. Placeholder color `#4B5563`.
- Focus state: border 1px solid `#3B82F6` with a crisp outer focus ring (`box-shadow: 0 0 0 1px #3B82F6`).

### Checkboxes & Radio Controls
Squared geometry (`0.125rem` radius for checkboxes, circular for radios). Border 1px solid `#4B5563`, background `#111827`. When selected: background `#3B82F6`, border `#3B82F6`, with a high-contrast white glyph.

### Lists & Telemetry Log Rows
Alternating row states are forbidden; separation is achieved via `1px solid #1F2937` borders.
- Default row background: `#111827`. Hover row background: `#1F2937`.
- Each row contains fixed-width slots: Timestamp (`label-sm`, `#6B7280`), Severity indicator, Source micro-badge, and Payload message (`code-inline`, `#E5E7EB`).

### Human-in-the-Loop AI Approval Card
A dedicated diagnostic component featuring a two-column split layout:
- **Left Panel (Hypothesis & Evidence)**: Background `#111827`, border 1px solid `#374151`, containing parsed telemetry spans, affected Kubernetes pods, and probability scores.
- **Right Panel (Action Plan)**: Dry-run terminal diff with suggested script executions, explicit parameter toggles, and dual action buttons: "Approve & Execute" (`#3B82F6`) and "Reject Hypothesis" (`Outline`).
